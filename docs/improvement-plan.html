1Interactive canvas — smart shapes & selection ★ new feature

Microsoft-Whiteboard-style behavior: freehand strokes snap to clean shapes, and everything becomes a selectable, movable vector object. Key insight: Fabric.js already stores every brush stroke as a vector Path — the canvas is just locked in drawing mode. Most of this is unlocking + a shape classifier, not a new engine.

✅ Implemented on this branch. New modules src/shape-classifier.js (pure geometry, unit-tested) + src/shapes.js (Fabric builders) + src/modes.js (modes, toolbar, Space-to-select, beautify hook); toolbar & "Smart shapes" selector added to public/index.html. Recognizer tests run via npm test. Build & server boot verified.

1.1 — Draw / Select / Shapes modes

✓ shippedHighdecided

Now: isDrawingMode is permanently true, so nothing can be selected or moved.

  • Toolbar toggle for Draw / Select / Shapes (primary interaction — decided).
  • Hold-a-modifier (e.g. Space) for temporary select without leaving Draw (decided).
  • Select mode flips isDrawingMode = false → native Fabric marquee multi-select, move, resize, rotate, delete, group. Existing pinch-zoom/pan keeps working.

1.2 — Ink → editable vector objects

✓ shippedHighmostly free

Strokes are already Fabric Path objects. Once Select mode exists they're immediately movable/scalable — no conversion layer needed. Beautified shapes (below) are even cleaner to edit via handles.

1.3 — Shape beautification on stroke completion

✓ shippedMediumset decided

On path:created, classify the stroke's points and, if it strongly matches a primitive, swap the wobbly path for a clean Fabric shape (with a snap animation + one-tap undo).

Beautify set (decided): straight lines · arrows · rectangles/squares · circles/ellipses.

  • Lightweight geometric classifier (line-fit residuals; closed-vs-open; corner detection via Ramer–Douglas–Peucker; radial-variance for circles; hook-detection for arrows). No heavy gesture library — keeps deps minimal and gives direct "snap straight" control.
  • Right-angle / square snapping for rectangles; equal-axis snapping for circles. Rectangle-vs-ellipse decided by corner counting (robust to shaky sides).
  • Keeps the original freehand stroke as a faded "ghost" (tag _isGhost) beneath the snapped shape, so drawn-vs-generated stays visible.

1.4 — "Smart Shapes" setting (Off / Manual / Auto)

✓ shippedHighdecided

User-selectable behavior in a settings panel, so snapping never fights handwriting:

  • Off — pure ink (today's behavior).
  • Manual (default) — snapping only fires in Shapes mode; Draw mode stays raw ink.
  • Auto — any strongly-matching stroke snaps even in Draw mode (the "magic", opt-in).

Why this matters: the app's core is OCR of handwritten equations. Defaulting to Manual keeps the crop-and-extract pipeline completely unaffected — a 2 never gets "beautified" into a circle.

2Conversational voice mode ★ new feature

A single realtime multimodal session that ingests the user's mic audio and a live video feed of the whiteboard on one synchronized stream — so the model perceives drawing and speech together (it sees a line being drawn as you say "make this steeper") and can ask clarifying questions in sync. A big step up from today's one-shot webkitSpeechRecognition (hardcoded to sv-SE). Larger, separate workstream from §1.

✅ First end-to-end slice on this branch. Server-side WebSocket relay (voice-server.js, key stays server-side) to a Gemini Live session, and a client src/voice.js behind a 🎤 Voice toggle that streams 16kHz mic PCM + ~1fps whiteboard JPEG frames and plays back 24kHz audio replies; transcripts go to the output panel. ⚠️ Requires HTTPS (mic blocked on plain http). Live model is GEMINI_LIVE_MODEL (default gemini-live-2.5-flash-native-audio).

2.1 — Realtime multimodal live session

✓ shipped (v1)bigger bet

Now: speech.js does single-utterance recognition, locale-locked to Swedish, no spoken responses, no vision.

  • Lead provider: Google Gemini Live API. Purpose-built to ingest continuous synchronized audio + video + text on one realtimeInput stream, explicitly avoiding cross-modality temporal misalignment. Native-audio live model family (e.g. gemini-live-2.5-flash-native-audio — confirm the current ID at build time).
  • Low-latency speech-in / speech-out with barge-in (interrupt mid-sentence). Fix the hardcoded locale while here.
  • OpenAI Realtime (GA, WebRTC) is the fallback, but its video is closer to on-demand frame snapshots than a continuous synced feed — less suited to this.

2.2 — Stream the whiteboard as live video, in sync with audio

✓ shipped (v1)

This is the core ask: the board is streamed as video into the model alongside the mic, not fed as periodic stills.

  • Board → video: canvasElement.captureStream(1) yields a live MediaStream of the Fabric canvas — no screen recording. Downscale frames to ≤768×768 at ~1 FPS (Gemini Live's recommended envelope; plenty for a whiteboard).
  • Mic → audio: 16 kHz PCM16 in; model replies at 24 kHz. Both pushed on the same realtime stream so they stay time-aligned.
  • The model references what's being drawn and asks clarifying questions by voice ("is that a 7 or a 1?", "plot both curves?") — exactly the requested behavior.

2.3 — Key security & cost gating

✓ key server-sidecost gating TODO
  • Never expose the Gemini key in the browser — proxy the Live session through the existing Express server (WebSocket relay) or mint ephemeral tokens.
  • Continuous video is the cost driver: only stream while voice mode is active; pause frames when the board is idle.

2.4 — Model acts on / draws back to the board

✓ shipped (v1)

The assistant now draws on the board via Gemini Live function-calling: tools for draw_line/rect/ellipse/arrow, write_text, plot_function, and erase/move/resize (spatial — it targets objects by location) + clear_board. Coordinates are 0-100% of the board; the browser (src/canvas-actions.js) converts and runs them through Fabric, then returns a result so the model can confirm. So "solve it and draw the graph" / "erase the circle" / "make it bigger" now actually happen on the canvas.

3AI models & APIs

The original headline: the app was built around model IDs and SDKs that have since been superseded — and in one case removed.

3.1 — Gemini path is broken in production

✓ shipped

Was: server.js called the shut-down gemini-2.0-flash via the deprecated @google/generative-ai SDK → 404, "Gemini" option dead.

  • ✅ Migrated to the GA @google/genai SDK on gemini-2.5-flash (env-overridable via GEMINI_MODEL; flip to gemini-3.5-flash with no code change).
  • ✅ Uses responseMimeType: 'application/json' for structured output — the markdown-fence regex is now just a defensive fallback.
  • ✅ Correct image mime type (was hardcoded image/png while the canvas exports JPEG).
⚙️ Deploy note: adds the @google/genai dependency — run npm install once on the host (the git watcher doesn't), then restart npm run dev.

3.2 — OpenAI models are generations behind

✓ shipped

Was: vision gpt-4o, solving gpt-4, via hand-rolled axios.

  • ✅ Adopted the official openai SDK; default model gpt-5.4 for both vision & solve (env-overridable via OPENAI_VISION_MODEL / OPENAI_SOLVE_MODEL — same 404 escape hatch as Gemini).
  • ✅ JSON response format for extraction; dropped the raw axios calls.
⚙️ Deploy note: adds the openai dependency — npm install on the host once, then restart npm run dev.

3.3 — Add Claude as a provider option

✓ shipped
  • ✅ providers/claude.js via the official @anthropic-ai/sdk, default claude-haiku-4-5 (env-overridable to claude-opus-4-8 for the hardest handwriting). Uses ANTHROPIC_API_KEY.
  • ✅ Added to the registry and the model dropdown ("Claude (Advanced)") — extraction & solving both routed through the unified /extract + /solve dispatch.
⚙️ Deploy note: adds @anthropic-ai/sdk and needs ANTHROPIC_API_KEY in .env. npm install on the host once.

3.4 — Unify the provider abstraction

✓ shipped

Was: /extract-equation and /extract-equation-gemini duplicated prompts/schemas/validation; the frontend branched on model name to pick a URL.

  • ✅ Single POST /extract with a provider field, over a small interface — providers/{openai,gemini}.js implement isConfigured() / extract(image) / solve(equation).
  • ✅ Shared prompt + validateExtraction in providers/schema.js; registry in providers/index.js; model IDs centralized & env-overridable. Old endpoints kept as thin aliases.
  • This same abstraction is where the voice mode (§2) plugs its realtime provider in.
