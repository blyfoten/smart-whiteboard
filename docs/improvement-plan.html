1AI models & APIs — the headline

The app was built around model IDs and SDKs that have since been superseded — and in one case removed entirely. This is where "a LOT has changed" bites hardest.

1.1 — Gemini path is broken in production

Broken now

Now: server.js calls gemini-2.0-flash via the @google/generative-ai SDK (^0.3.0) for both /solve and /extract-equation-gemini.

Google shut down Gemini 2.0 Flash on June 1, 2026 — those requests now return 404. The "Gemini (Advanced)" dropdown option is effectively dead.

  • Migrate to a current model — Gemini 3.5 Flash (GA, fast/cheap, good fit for this app) or Gemini 3 Pro for harder reasoning.
  • Replace the deprecated @google/generative-ai package with the GA @google/genai SDK (the old one is end-of-life; new features ship only on the new SDK).
  • Use native structured-output / JSON-schema response support instead of the current "ask for JSON, then regex it out of a markdown code fence" hack.

1.2 — OpenAI models are several generations behind

High

Now: vision extraction uses gpt-4o; text solving uses gpt-4 (raw axios POST to /v1/chat/completions).

  • Move to the current lineup — GPT-5.5 (flagship) or GPT-5.4 / 5.4-mini for a cheaper, faster path. gpt-4 for solving is the most dated call in the codebase.
  • Adopt the official openai SDK instead of hand-rolled axios calls — gets retries, typing, and structured outputs for free.
  • Use structured outputs (JSON schema) so the extraction endpoint can't return malformed JSON — deletes a whole class of parse-error handling.

1.3 — Add Claude as a provider option

Mediumnew capability

Claude is a natural third backend here: strong handwriting/diagram vision, and first-class structured outputs (output_config.format with a JSON schema) that map directly onto the app's { dependentVariable, expression, scope, ranges } contract.

  • Use the official @anthropic-ai/sdk. Suggested models: claude-haiku-4-5 (cheap/fast for extraction) or claude-opus-4-8 / claude-sonnet-4-6 for the hardest handwriting.
  • Vision + structured outputs in a single call replaces the OpenAI Vision → parse → validate dance.

1.4 — Unify the provider abstraction

High

Now: /extract-equation (OpenAI) and /extract-equation-gemini are separate endpoints with duplicated prompts, schemas, and validation; the frontend branches on model name to pick a URL.

  • One endpoint — e.g. POST /extract with a provider field — backed by a small provider interface (extract(image), solve(equation)).
  • Single shared JSON schema + prompt, defined once. Per-provider files (providers/openai.js, gemini.js, claude.js, mathjs.js) implement the interface.
  • Centralizes model IDs (no more hardcoded strings scattered in server.js) and makes "swap the model" a one-line change.

2Security & configuration

Small but important fixes around secrets and failure modes.

2.1 — Validate API keys at startup

High

Now: missing OPENAI_API_KEY / GEMINI_API_KEY isn't checked — calls just fail at request time with opaque errors.

Fail fast on boot (or clearly disable a provider in the UI when its key is absent), so a misconfigured deploy is obvious.

2.2 — Tighten request handling

Medium
  • Lock down CORS (currently wide-open cors()) to known origins.
  • Add basic rate limiting on the AI endpoints — image calls are billable.
  • Trim verbose console.log of raw model responses / equations in server.js.

3Code architecture & quality

The phase-1 refactor already split the frontend monolith into modules. These build on that.

3.1 — Remove the dual button-wiring

Medium

Now: several buttons (Solve, Clear, model select, test-equation) are wired both in src/ui.js and in the inline <script> in public/index.html, bridged via window.* globals.

Pick one home (the bundle), delete the inline duplicates, and drop the window bridge. Reduces "why did this fire twice?" confusion.

3.2 — Add a test suite

High

Now: no tests, no linter; npm test is a no-op.

  • Unit tests for the pure logic — /graph point sampling, JSON extraction/validation, the provider interface (mocked).
  • Add ESLint + a formatter so future changes stay consistent.

3.3 — Production build & dependency refresh

Nice-to-have
  • Default deploys to build:prod; serve hashed bundles. Webpack currently defaults to dev mode.
  • Audit / bump deps (Fabric, Chart.js, Express) and wire up the AI SDKs above.
  • Remove leftover scratch files (public/test.html) if unused.

5Suggested sequencing

A rough order of operations — happy to reshuffle.

  1. Unbreak & modernize the AI layer

    Fix Gemini (1.1), refresh OpenAI models + SDK (1.2), introduce the provider abstraction (1.4). Restores full functionality and removes the duplicated extract endpoints.

  2. Harden config & secrets

    Key validation (2.1), CORS + rate limiting + log hygiene (2.2). Quick wins once the AI layer is in flux anyway.

  3. Add Claude + structured outputs everywhere

    Third provider (1.3) on top of the now-clean abstraction; switch all providers to schema-validated JSON output.

  4. Quality net

    Tests + lint (3.2), de-duplicate button wiring (3.1), production build (3.3).

  5. Product bets

    Pick from section 4 based on where you want to take the app.
